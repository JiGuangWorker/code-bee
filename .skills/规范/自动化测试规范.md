# 自动化测试规范（总览）

> **适用角色：** 所有工程师
> **对标原则：** 《第一条 交付诚信原则》
> **关联规范：** [TDD规范](../需求与质量规范/TDD规范.md)、[QA规范](../需求与质量规范/QA规范.md)
> **版本：** v1.0

## 一、定位

本文件是自动化测试规范的**总览索引**。具体工程实施标准拆分到四个独立文件：

| 文件 | 覆盖内容 |
|------|----------|
| [后端单元测试规范](后端单元测试规范.md) | 方法级覆盖原则、场景覆盖维度、AAA 测试结构 |
| [后端Mock与分层测试规范](后端Mock与分层测试规范.md) | 三层 Mock 策略（testify/mock + sqlmock）、隔离写法 |
| [前端单元测试规范](前端单元测试规范.md) | 组件/Hook/工具函数测试、vitest + testing-library、data-testid 约束 |
| [E2E测试规范](E2E测试规范.md) | 基于 Mock 服务的 Playwright 端到端测试、页面流程、组件联动、视觉回归 |

## 二、三层规范体系

```
TDD规范（方法论）
    ↓ 怎么设计测试：Red-Green-Refactor、AAA、命名

自动化测试规范（工程标准）── 本文件索引
    ├── 后端单元测试规范         # 测什么：方法级覆盖、场景维度、AAA 结构
    ├── 后端Mock与分层测试规范   # 怎么测：三层 Mock 隔离策略
    ├── 前端单元测试规范         # React：组件测试 / Hook 测试 / 工具函数测试
    └── E2E测试规范              # Playwright + Mock 后端

QA规范（流程防线）
    ↑ 怎么验收测试：提测标准、验收准出、Bug 管理
```

## 四、Mock E2E 的核心设计

```
Go 接口定义（调用方定义接口）
    ├── 真实实现 → 生产环境路由注入
    └── Mock 实现 → E2E 测试路由注入
                        ↓
              Playwright 浏览器自动化
                测试前端 + Mock 后端
```

> 不需要真实数据库、不需要外部依赖。前端是真实的，后端服务用 Mock 替代。详细实施见 [E2E测试规范](E2E测试规范.md)。

## 五、Makefile 统一入口

```makefile
# 后端单元测试
test-backend-unit:
	cd backend && go test ./internal/... -short -count=1

# 前端单元测试
test-frontend-unit:
	cd frontend && pnpm test

# E2E 测试
test-e2e:
	cd frontend && npx playwright test --config tests/playwright.config.ts

# CI 全量
test-ci: test-backend-unit test-frontend-unit test-e2e
```

## 六、CI 门禁

```
代码推送
  ├── make lint                   # 静态分析
  ├── make test-backend-unit      # 后端单元测试 + 覆盖率检查
  ├── make test-frontend-unit     # 前端单元测试
  ├── make test-e2e               # E2E（Mock 后端 + Playwright）
  └── 全部通过 → 允许合并
```

> 任何门禁失败 = 阻断合并。不得跳过、不得注释掉失败测试。
