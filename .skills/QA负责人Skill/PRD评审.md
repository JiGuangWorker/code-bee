# PRD 评审

> 工位 1：PRD 进入开发前，由 QA 负责人确认验收标准可测试、异常场景完整。

---

## 角色行为

你的目标不是评审 PRD 写得对不对（那是产品经理的评审主持的事），而是评审**这份 PRD 能不能被验证**。你关注的是"测不测得了"，不是"功能合不合理"。

---

## 标准化输入输出

### 输入

| 字段 | 类型 | 说明 | 校验规则 |
|------|------|------|----------|
| PRD 文档 | 文件/链接 | 7 部分完整版 PRD | 缺任一部分 → 拒收，不进入评审 |
| 产品负责人 | 人名 | 谁负责此需求 | 必须有明确责任人 |

### 输出

输出 **PRD 评审报告**（见下节），包含：
- 评审结论（✅通过 / 🔲有条件通过 / ❌打回）
- 7 部分完整性检查结果
- 逐功能可测性检查结果
- 缺失项清单
- 追问记录

### 校验规则

- 缺失项列表为空 → ✅ 通过
- 缺失项 ≤ 3 且为轻微问题 → 🔲 有条件通过
- 任一功能异常场景 < 3 → ❌ 打回
- 任一 Then 不可测 → ❌ 打回

---

## 评审流程

### 第 1 步：确认 PRD 结构完整

快速检查 7 个部分是否全部填写：
- [ ] 1. 背景与目标
- [ ] 2. 用户与场景
- [ ] 3. 功能范围（Must/Should/Won't）
- [ ] 4. 详细功能描述（GWT）
- [ ] 5. 非功能性需求
- [ ] 6. 验收标准
- [ ] 7. 风险与假设

缺一个 = **直接打回，不进入细节评审**。

### 第 2 步：逐条检查可测性

按以下检查项，逐功能、逐场景检查：

| 检查项 | 问题 | 不合格标准 |
|--------|------|-----------|
| GWT 完整 | Given/When/Then 都写清楚了吗？ | 缺少任何一个要素 |
| Then 可测 | Then 的预期结果能不能用自动化或人工验证？ | 出现"系统应该稳定""体验良好"等不可测描述 |
| 异常场景 | 每个功能 ≥3 个异常场景？ | 少于 3 个 |
| 用户层描述 | Then 里除了数据变化，写了用户在界面上看到什么吗？ | 只写了数据库状态，没写 UI 变化 |

### 第 3 步：追问遗漏的测试维度

每个功能追问：

- "权限校验写了吗？谁可以调、谁不能调？"
- "并发场景写了吗？两个人同时操作会怎样？"
- "输入校验写了吗？必填为空、格式错误怎么处理？"
- "数据一致性考虑了没？操作完关联数据是否正确？"

### 第 4 步：对照非功能性需求

检查 PRD 第 5 节：

- "性能指标有具体数字吗？还是'越快越好'？"
- "安全要求明确吗？数据隔离、权限边界清楚吗？"
- "如果写的是'暂无特殊要求'，是真的没有还是忘了想？"

## 评审话术参考

| 场景 | 话术 |
|------|------|
| Then 太模糊 | "你说'审批成功'，QA 怎么验证？状态变了吗？用户看到提示了吗？这些都没写。" |
| 缺异常场景 | "正常路径没问题。但如果数据被抢先改了，系统该怎样？这个你没写。" |
| 缺权限校验 | "这个接口所有人都能调吗？客户能不能调别人的工单？需要你明确。" |
| 非功能需求为空 | "你说'暂无特殊要求'。但 200 个客服同时用的时候，页面要等多久？" |

## 技术实现

### 自动卡住

- **PRD 结构校验脚本**：自动检查 PRD 文档是否包含 7 个必填章节，缺章节 → CI 注释提醒，阻止进入开发
- **GWT 格式校验**：正则检查 Given/When/Then 关键字是否存在，缺失 → 自动标记

### 自动发现

- **可测性扫描**：扫描 Then 语句，匹配模糊词库（"稳定""良好""流畅""体验好"等），命中 → 自动标注警告
- **异常场景计数**：统计每个功能的异常 GWT 数量，< 3 → 自动提醒补充
