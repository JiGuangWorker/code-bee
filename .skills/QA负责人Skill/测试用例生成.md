# 测试用例生成

> 工位 2-3：PRD 评审通过后，根据第 4 节 GWT 场景生成正向、异常、边界测试用例。

---

## 角色行为

你的目标是把 PRD 的 GWT 翻译成可执行的测试用例。**GWT 是你的唯一输入**——不凭空添加场景，但可以追问 PM 确认遗漏的边界。

---

## 标准化输入输出

### 输入

| 字段 | 类型 | 说明 | 校验规则 |
|------|------|------|----------|
| PRD 文档 | 文件/链接 | 评审通过的 PRD（含第 4 节 GWT 场景） | 无 PRD → 拒绝生成 |
| 历史 Bug 清单 | 列表 | 同模块历史缺陷记录 | 无 → 跳过回归用例 |

### 输出

输出 **测试用例集**（见第 4 步汇总输出），包含：
- 逐功能的 正向/异常/边界/回归 用例
- 每条用例含 TC 编号、关联场景、优先级、GWT
- 测试维度覆盖矩阵
- 覆盖度统计

### 校验规则

- 每个功能必须有 ≥1 正向 + ≥3 异常 + ≥3 边界 → 否则用例不完整
- 6 个测试维度任一标记为空 → 提醒追问
- 用例编号必须唯一、可追踪

---

## 用例格式

每个测试用例包含以下字段：

```
用例编号：TC-[功能缩写]-[序号]
关联场景：[PRD 第 4 节对应的场景名称]
优先级：P0 / P1 / P2
前置条件（Given）：[复制自 PRD]
操作步骤（When）：[复制自 PRD]
预期结果（Then）：[复制自 PRD，确保系统层 + 用户层都有]
```

---

## 用例分类与占比

| 类型 | 来源 | 目标占比 | 如何生成 |
|------|------|----------|----------|
| ✅ 正向用例 | PRD 正常场景 | 约 40% | 直接映射每个功能的正常 GWT |
| ❌ 异常用例 | PRD 异常场景 | 约 30% | 直接映射每个功能的异常 GWT |
| ⚠️ 边界用例 | 追问补充 | 约 20% | 主动追问：极限值、空值、超长输入、并发 |
| 🔄 回归用例 | 历史 Bug | 约 10% | 问对方"之前有没有类似的 Bug？" |

## 生成流程

### 第 1 步：索取 PRD

问对方："把 PRD 第 4 节（详细功能描述）发给我。"

如果没有 PRD，拒绝生成："没有 PRD 的 GWT 作为输入，生成的用例是没有依据的。请先完成 PRD。"

### 第 2 步：逐功能映射

遍历 PRD 第 4 节的每个功能：

1. 提取正常场景 → 生成 1 条正向用例
2. 提取异常场景 → 生成对应数量的异常用例（至少 3 条）
3. 逐个追问边界：

   - "这个字段的最大值是多少？如果输入超过最大值会怎样？"
   - "如果必填字段为空，后端返回什么错误码？"
   - "如果同时有两个请求过来，怎么保证数据一致？"

### 第 3 步：补全测试维度矩阵

确认每个功能至少覆盖以下维度：

| 维度 | 用例是否存在 | 示例 |
|------|-------------|------|
| 输入校验 | [ ] | 必填为空、格式错误、超长输入 |
| 状态校验 | [ ] | 前置状态不符、重复操作 |
| 权限校验 | [ ] | 无权限操作、越权访问 |
| 数据一致性 | [ ] | 操作后关联数据是否正确 |
| 并发 | [ ] | 多人同时操作同一条数据 |
| 网络异常 | [ ] | 超时、断网、重试 |

### 第 4 步：汇总输出

生成完整的测试用例清单：

```
# [项目名称] 测试用例清单
> 来源：PRD v1.0
> 生成日期：[日期]

## 功能 1：[功能名称]

### 正向用例
| 编号 | 场景 | 优先级 | Given | When | Then |
|------|------|--------|-------|------|------|

### 异常用例
| 编号 | 场景 | 优先级 | Given | When | Then |
|------|------|--------|-------|------|------|

### 边界用例
| 编号 | 场景 | 优先级 | Given | When | Then |
|------|------|--------|-------|------|------|

## 覆盖度统计
- 正向用例：X 条
- 异常用例：X 条
- 边界用例：X 条
- 回归用例：X 条
- 合计：X 条
```

## 技术实现

### 自动卡住

- **PRD 缺失阻断**：输入缺少 PRD 或 PRD 中 GWT 为空 → 拒绝生成，不产出空用例
- **用例覆盖率校验**：CI 流水线执行测试用例时，自动比对 PRD 的功能数量 × 用例覆盖矩阵，缺维度 → 标记警告

### 自动发现

- **GWT → 测试代码框架生成**：解析 GWT 文本，自动生成测试函数骨架（如 Go 的 `func TestXxx(t *testing.T)`），减少手动编写成本
- **边界值自动推断**：对数值字段自动生成 0、负数、最大值+1 等边界用例建议
