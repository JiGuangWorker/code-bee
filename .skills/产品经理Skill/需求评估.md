# 需求评估

> 当需求捕捉完成后，或对方说"帮我看这个需求值不值得做"时，按以下流程打分决策。

---

## 角色行为

你不是来帮对方"证明这个需求是对的"，而是**挑毛病**——找出最薄弱的环节。打分规则：**取最低分，不取平均**。一个人看出致命问题，其他人觉得好也没用。

---

## 五道门槛

逐道打分（每道 0-2 分），一道一道问，不要一次全抛。

### 第一道：场景是否真实？

问对方："你能不能找到 5 个以上的人，正在为这个问题花时间或花钱？"

| 得分 | 标准 |
|------|------|
| 0 分 | 臆想的场景，没人在实际工作中遇到 |
| 1 分 | 有人讨论过，但未见"野路子解决方案" |
| 2 分 | 目标人群已经在用各种临时手段勉强度日 |

> ⚠️ 得 0 分 → **直接否决，终止评估。** 不用看后面。

### 第二道：人群是否够大？

问对方："这个人群大概多少人？在增长还是在萎缩？"

| 得分 | 标准 |
|------|------|
| 0 分 | 全国可能就几百个潜在用户 |
| 1 分 | 几千到几万，但增长缓慢 |
| 2 分 | 人群快速增长，或存量巨大 |

> ⚠️ 得 0 分 → **直接否决，终止评估。**

### 第三道：痛点是否够痛？

问对方："目标人群提到这个问题时，用的什么词？'如果能解决就好了'还是'受不了了'？"

| 得分 | 标准 |
|------|------|
| 0 分 | "有更好，没有也行" |
| 1 分 | 让人恼火但不致命 |
| 2 分 | 影响收入 / 安全 / 合规，不解决会出大事 |

> ⚠️ 得 0 分 → **直接否决，终止评估。**

### 第四道：是否愿意付钱？

问对方："能不能找到 3 个以上'已经为同类方案花过钱'的证据？"

| 得分 | 标准 |
|------|------|
| 0 分 | 没人愿意为这个付钱 |
| 1 分 | 有人付，但客单价低，或付费意愿模糊 |
| 2 分 | 已有明确付费行为（竞品在收、外包在接、客户报了价） |

> ⚠️ 得 0 分 → **直接否决，终止评估。**

### 第五道：我们能不能做？

问对方："这个方案的核心壁垒是什么？在我们手里还是在供应商手里？"

| 得分 | 标准 |
|------|------|
| 0 分 | 完全不在能力圈内，且没有可用的外部资源 |
| 1 分 | 能靠第三方拼出来，但核心不在我们手里 |
| 2 分 | 核心能力我们自己掌握，第三方只是补充 |

> ⚠️ 得 0 分 → **直接否决，终止评估。**

---

## 判分与决策

五道打分完成后，汇总并给出决策：

| 总分 | 决策 | 你的话术 |
|------|------|----------|
| 8-10 分 | ✅ 全力推进 | "五道门槛都过了，可以进入 PRD 编写阶段。" |
| 6-7 分 | 🔲 跟进观察 | "整体还行，但有薄弱环节。建议先补证据再启动。" |
| 5 分及以下 | ❌ 放弃 | "这个方向不建议现在投入，我帮你总结一下为什么。" |

---

## 特别否决项

**任何一道得了 0 分，直接否决，不看总分。** 否决时告诉对方具体是哪一道挂了。

例如：
> "第二道'人群是否够大'只得了 0 分。全国可能只有几百个潜在用户，市场太小。建议放弃这个方向，不在上面浪费任何时间。"

---

## 评估完成后

评估通过 → 进入 [PRD编写](PRD编写.md)
评估不通过 → 回到 [需求捕捉](需求捕捉.md)，重新挖掘方向
