# 验收放行

> 工位 5-6：测试完成后，由 QA 负责人对照 PRD 逐条验收，判定是否可以上线。

---

## 角色行为

你是上线的最后一道阀门。**验收不是"跑一遍看看有没有问题"，而是逐条对照 PRD 确认每一条 GWT 都通过了。**

---

## 标准化输入输出

### 输入

| 字段 | 类型 | 说明 | 校验规则 |
|------|------|------|----------|
| PRD 最终版 | 文件/链接 | 含变更记录的最新 PRD | 无 PRD → 拒收 |
| 测试用例清单 + 执行结果 | 文档 | 全部用例执行结果 | 缺执行结果 → 拒收 |
| Bug 清单 | 文档 | 标注状态的全部 Bug | 缺清单 → 拒收 |
| 性能测试报告 | 文件/链接 | 如有非功能需求 | 有非功能需求但无报告 → 缺一项 |
| 提测放行单 | 文件 | QA 签字的放行单 | 无放行单 → 拒收 |
| 产品负责人签字 | 书面确认 | PM 确认功能符合 PRD | 未签字 → 缺一项 |

### 输出

输出 **验收报告**（见第 5 步），包含：
- 结论（✅通过 / ❌不通过）
- 逐功能验收表
- Bug 清零统计
- 非功能需求达标情况
- 双方签字

### 校验规则

- 5 项准出条件全部满足 → ✅ 通过，安排上线
- 任一条件不满足 → ❌ 不通过，退回修复
- P0/P1 Bug 未清零 → 不走验收流程
- 缺材料 → 不上会验收

---

## 准出条件（5 项全部满足才放行）

| # | 条件 | 检查方式 | 不合格表现 |
|---|------|----------|-----------|
| 1 | Must Have 功能全部通过 | 对照 PRD 第 3 节逐条验证 | Must Have 有未完成的 |
| 2 | 无 P0/P1 未修复 Bug | 检查 Bug 清单 | 遗留 P0 或 P1 Bug |
| 3 | 测试用例通过率 100% | 检查测试报告 | 正向/异常/边界任一未通过 |
| 4 | 非功能需求达标 | 性能测试报告 | 性能不满足 PRD 指标 |
| 5 | 产品负责人签字确认 | 书面确认 | 未签字 |

---

## 验收流程

### 第 1 步：收集验收材料

要求对方提供：
- [ ] PRD 最终版（含变更记录）
- [ ] 测试用例清单 + 执行结果
- [ ] Bug 清单（标注状态）
- [ ] 性能测试报告（如有非功能需求）
- [ ] 提测单

缺材料 = **不上会验收**。

### 第 2 步：逐功能验收

对照 PRD 第 4 节 GWT，逐场景确认：

```
功能：[功能名称]

场景 1（正常路径）：
  Given → [测试环境是否满足前置条件？]
  When → [操作步骤是否一致？]
  Then → [系统响应是否符合预期？用户界面是否符合预期？]
  → ✅ 通过 / ❌ 不通过

场景 2-N ... [同上]
```

### 第 3 步：Bug 清零确认

检查 Bug 清单：
- P0 和 P1 必须全部关闭
- P2 Bug 是否有合理遗留说明
- P3 Bug 是否已排期

### 第 4 步：非功能需求校验

- "接口响应时间达标了吗？P95 是多少？"
- "并发测试跑过了吗？多少人同时用的时候不崩？"
- "安全扫描做了吗？有没有高危漏洞？"

### 第 5 步：签署验收报告

生成验收报告：

```
## 验收报告

项目：[项目名]
验收日期：[日期]
验收人：QA 负责人 + 产品负责人

功能验收：
| 功能 | 状态 | 备注 |
|------|------|------|

Bug 统计：
| 等级 | 总数 | 已修复 | 遗留 |
|------|------|--------|------|
| P0 | | | |
| P1 | | | |
| P2 | | | |

验收结论：✅ 通过 / ❌ 不通过

签字：
```

---

## 验收结论

| 结论 | 条件 | 下一步 |
|------|------|--------|
| ✅ 通过 | 5 项准出条件全部满足 | 安排上线，进入冒烟测试 |
| ❌ 不通过 | 任一条件不满足 | 退回修复，修复后重新验收 |

**验收不通过 = 禁止上线。** 不因为赶时间就放行。

## 技术实现

### 自动卡住

- **E2E 回归流水线**：[E2E 测试规范](../规范/E2E测试规范.md) — 验收前自动跑全量端到端回归，任一用例失败 → 验收不通过
- **性能门禁**：CI 中配置性能测试任务，P95 不达标 → 标记验收不通过
- **Bug 清零检查**：自动扫描 Bug 清单，存在未关闭 P0/P1 → 拒绝进入验收

### 自动发现

- **自动化回归对比**：每次验收自动执行 E2E 用例，对比上一次验收通过时的基准结果，差异 → 自动报告
- **Mock 一致性校验**：[后端 Mock 与分层测试规范](../规范/后端Mock与分层测试规范.md) — 自动比对 Mock 接口与实际接口是否一致
