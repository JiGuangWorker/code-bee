# 部署规范

> **适用角色：** 所有工程师
> **对标原则：** 《第一条 交付诚信原则》
> **版本：** v1.0

---

## 一、部署工具选型

| 决策 | 说明 |
|------|------|
| **工具** | Gokins CLI（Go 单二进制） |
| **禁止** | Python / Node.js / Java 运行时依赖 |
| **禁止** | Ansible、Helm 等重型框架 |
| **禁止** | sshpass + scp 拼凑脚本 |

> Gokins CLI 是 Go 语言编写的单二进制轻量部署工具，无需 Web 服务即可执行部署，必要时可切换为带认证的常驻服务模式。

---

## 二、使用方式

### 2.1 本地调试 / 手动部署（CLI 模式）

```bash
# 通过 Makefile 统一入口
make deploy

# 或直接调用 CLI
gokins deploy
```

> CLI 模式无需启动 Web 服务、无需配置账号密码，直接执行部署任务。

### 2.2 团队协作 / Git Webhook 自动触发（服务模式）

仅在需要 Webhook 自动触发或多人协作时，启动带认证的常驻服务：

```bash
gokins server --port 8080 --auth-token <token>
```

## 三、配置文件

项目根目录下的 `.gokins.yaml`：

```yaml
# Gokins CLI 部署配置
# 用法: gokins deploy

# 目标服务器
targets:
  - name: staging
    host: <staging-server-ip>
    port: 22
    user: deploy
    # 认证方式：SSH Key（推荐）或密码
    auth:
      key: ~/.ssh/deploy_rsa
    # 部署路径
    path: /opt/app/staging

  - name: production
    host: <production-server-ip>
    port: 22
    user: deploy
    auth:
      key: ~/.ssh/deploy_rsa
    path: /opt/app/production

# 构建产物
artifact:
  # 后端二进制
  backend: backend/bin/server
  # 前端构建产物
  frontend: frontend/packages/app/dist

# 部署前执行的命令
pre_deploy:
  - go build -o backend/bin/server ./backend/cmd/server
  - cd frontend && pnpm build

# 部署后执行的命令（如重启服务）
post_deploy:
  - systemctl restart myapp

# 健康检查
health_check:
  url: http://localhost:8080/health
  retries: 5
  interval: 3s
```

### 配置要点

| 配置项 | 说明 |
|--------|------|
| `targets` | 部署目标服务器列表，支持多环境 |
| `artifact` | 构建产物路径，支持多文件 |
| `pre_deploy` | 部署前本地执行的构建命令 |
| `post_deploy` | 部署后在目标服务器执行的命令 |
| `health_check` | 部署后健康检查，全部重试失败则回滚 |

## 四、Makefile 集成

```makefile
# 部署（Gokins CLI 模式）
deploy:
	@echo "→ Gokins CLI 部署..."
	gokins deploy

# 指定环境部署
deploy-staging:
	gokins deploy --target staging

deploy-prod:
	gokins deploy --target production
```

## 五、CI/CD 集成

CI 流水线定义按平台要求放置（如 `.github/workflows/`），但部署逻辑通过 Makefile 收敛至 `deploy/` 目录和 `.gokins.yaml` 配置：

```yaml
# .github/workflows/deploy.yml（示例）
- name: Deploy to Staging
  run: make deploy-staging
```

> CI 定义是平台的契约，部署逻辑是团队的业务代码，二者分离。

## 六、目录关联

```
项目根目录/
├── .gokins.yaml          # 部署配置（声明式）
├── Makefile              # make deploy 统一入口
└── deploy/               # 部署资产（Dockerfile、K8s YAML 等）
    ├── Dockerfile
    ├── k8s/
    └── scripts/
```

## 七、强制规则

| 规则 | 说明 |
|------|------|
| ❗ 必须使用 Go 单二进制工具 | 禁止引入 Python/Node.js/Java 运行时 |
| ❗ 配置文件放根目录 | `.gokins.yaml` 与 `go.mod` 同级 |
| ❗ 部署资产统一放 `deploy/` | Dockerfile、K8s YAML 等不散落各处 |
| ❗ 本地调试用 CLI 模式 | 无需启动 Web 服务 |
| ❗ CI 中通过 Makefile 调用 | 不直接调 CLI，保持入口统一 |
